Two cryptographic systems, not one

The single most common confusion: the data protecting the card and the data protecting the PIN are different systems, different keys, different owners. Keep them apart and everything else falls into place.
EMV cryptogram (ARQC) — generated inside the chip using the issuer's keys (Issuer Master Key → card Unique Derived Key → per-transaction session key, indexed by the ATC counter). It proves the card is genuine to the issuer. The terminal can only carry it, never read or forge it.
DUKPT — the terminal/acquirer system that encrypts the PIN block (and optionally card data). Base Derivation Key → injected IPEK → a fresh key for every transaction, indexed by the KSN counter. It protects the PIN in transit between terminal and bank.
Both happen to use an incrementing counter (ATC vs. KSN) — which is exactly why they get blurred together.

The routing fork

A transaction is "on-us" or "not-on-us", and that decides who sees it.
On-usAcquirer and issuer are the same bank. The message never leaves the institution; no switch, no interchange.
Not-on-usDifferent banks. The request is routed by card BIN through a switch.
BKMBankalararası Kart Merkezi — Turkey's national interbank switch (live as a router since 1993). Routes and later clears/settles domestic card traffic between member banks.
SchemeFor cross-border or scheme-routed traffic, Visa / Mastercard networks switch the message to the foreign issuer and add FX + scheme fees.
HSMHardware Security Module. Verifies the ARQC, generates the ARPC, and performs PIN translation. Keys are created, used, and destroyed inside it; they never appear in host memory.
